# Issue Tracker

This tracker keeps active out-of-plan issues and a compact index of verified
resolutions or documented investigation closures.

## Tracker Rules

- Issue IDs use `GRV-Issue-NNN`. The next available ID is `GRV-Issue-148`.
- Assign an ID when an issue enters this tracker and preserve it through
  closure; never delete or reuse it. Check Git history before advancing or
  repairing the counter. Unknown historical IDs stay reserved rather than
  acquiring an inferred cause.
- Add unresolved concerns with concrete evidence to `Active Issues`. Keep each
  entry self-contained: affected area, reproducer, source revision, impact,
  priority and next action. Ignored artifacts are supplemental, not a
  prerequisite for reproducing or continuing the issue.
- Keep each item scoped tightly enough to fix and verify independently. Resolve
  related issues together when they share an owner, retaining each ID and its
  own regression evidence. Link active plans rather than duplicating their work.
- Record the date on the item, not in this filename.
- After verification, replace the active entry with a compact `Resolved Issues`
  row: the same ID, resolution/closure date, brief outcome and an evidence link.
  Keep detailed root causes, decisions and validation in an existing completion
  record, regression or fix commit rather than duplicating them in this index.
- Distinguish verified fixes, mitigations and investigations closed without a
  reproduced defect. A closed investigation does not establish a runtime fix or
  an attributed cause; preserve its limits and recurrence guidance in the
  record.
- Resolved means verified in source or closed by documented decision, not
  released. Add release/version claims only when separately confirmed. Retain
  prior evidence when new findings change an issue's status.
- Preserve existing issue anchors when compacting entries so inbound links
  continue to reach their issue. New rows may use a short `grv-issue-nnn`
  anchor.
- Do not use this tracker as a substitute for tests, benchmarks or release
  notes.
- Performance issues should stay in
  [`benchmark-signal-hardening-backlog.md`](benchmark-signal-hardening-backlog.md)
  unless they become a confirmed runtime defect. Do not add performance issues
  here until they have been investigated and confirmed as runtime defects.

## Active Issues

### Validation Workflow

- Use package references for normal development and release validation.
- Use `UseLocalLsfStack=true` only when an unreleased lower-stack change must be
  validated across sibling repositories.
- Resolve defects in the repository that owns the behavior, then release and
  validate packages in dependency order.
- Before release, run Gravitas `Release`, `ReleaseLean`, coverage, replay,
  allocation, and relevant benchmark gates against package dependencies.
- Keep volatile test and coverage counts in generated reports or dated
  verification records rather than this active section.

### GRV-Issue-144 - Context reset retains ended collider references in reusable storage

- **Recorded:** 2026-10-27. **Priority:** P2. **Owner:** Gravitas
  context/service reset.
- **Verified on:** `3f0b759` (.NET 10, coordinated local stack), before Phase 9
  runtime changes. This is bounded retention through old capacity, not evidence
  of an unbounded allocation leak or a collision-result defect.
- **Reproducer:** Keep a `GravitasWorldContext` alive, initialize a dynamic 3D
  sphere (or zero-core capsule) and bodyless static 2D members, obtain mixed
  contacts, then call `context.Reset()` and retire the host references. A
  no-inline factory returning weak collider references followed by
  `GC.Collect()`, `GC.WaitForPendingFinalizers()`, `GC.Collect()` still finds
  the retired mover alive. Explicit deactivation before disposal releases the
  same fixture. Keeping a disposed internal declaration alive also retains its
  context and exposes the same pre-existing reset ownership boundary.
- **Cause:** `ColliderRegistry.Clear()` clears indexed lookup but uses
  `_liveColliders.FastClear()`, retaining collider references in its backing
  array. Dimensional service refresh/snapshot buffers also use `FastClear()`.
  Declaration invalidation already releases its own cached mover/member roots;
  clearing the declaration alone cannot release these context-owned roots.
- **Impact:** A retained reusable context can keep ended collider/body/host
  graphs alive until the old reference slots are overwritten or the context is
  collected. Audit pure 2D, 3D and mixed reset parity together.
- **Next action:** Reproduce registry/service ownership independently through
  public lifecycle behavior, release populated reference slots at reset while
  retaining capacity, and verify reset/reuse, pool ownership and warm baselines.
  Do not broaden #143's completed-query contract into an unmeasured reset
  rewrite.

### GRV-Issue-147 - Closed convex mesh containment is missed for cylinders

- **Recorded:** 2026-10-29. **Priority:** P2. **Owner:** ordinary 3D closed-convex
  mesh/cylinder narrow phase.
- **Verified on:** Frozen Gravitas `9175653` and the Phase 14 public-API candidate
  based on `2ee3af9`, Windows x64/.NET 10 Release. No static-surface declaration
  is involved. This predates the documentation clarification and Phase 13/14.
- **Reproducer:** Use pure 3D at 16 Hz, grid `[-8,8]` on every axis, zero gravity,
  air density, damping and minimum speed. Register a bodyless unit-transform
  `LSMeshCollider` in `MeshColliderMode.Convex`: take the cube vertices/indices
  from `MeshTestFixtures.CreateConvexCube` and multiply its authored vertex
  coordinates by two, giving bounds `[-1,1]` on every axis. Place a mass-one
  dynamic cylinder at the origin, radius `0.25`, height `0.5`, frozen rotation,
  sleep disabled and manual grounding. Advance `Simulate` plus `LateSimulate`.
- **Observed:** The cylinder remains at raw position `(0,0,0)`, wholly within
  the filled convex hull. An otherwise identical radius-0.25 sphere receives
  response and moves to raw `(0,0,-4260607622)`. Exterior controls starting at
  X=`1.125`, Y=Z=0 receive wall response for both shapes, ending at raw
  `(5226975206,0,0)`. The original/current captures agree exactly.
- **Cause:** `DoMeshCylinderCheck` unconditionally uses
  `MeshTriangleContactGenerator.TryBuildMeshCylinderManifold`; that owner gathers
  only triangles intersecting the cylinder bounds and has no closed-convex
  volume fallback. The enclosed cylinder reaches no wall triangles. Sphere
  dispatch explicitly selects whole-hull volume contact for closed `Convex`
  meshes. Concave-mode closed-shell behavior is a different, intentional policy.
- **Impact:** Initial cylinder containment in a closed convex mesh receives no
  discrete response. No claim of observed sweep tunneling or mixed-mode failure
  is made by this reproduction.
- **Next action:** Add the contained/exterior controls as production regressions;
  establish filled-volume cylinder/hull contact through the appropriate existing
  math/physics owners. Preserve open/Concave surface semantics, exact witnesses,
  reversed order, transformed whole-shape checks and warm performance; audit
  corresponding mixed/query behavior before extending the claimed defect.
- **Evidence:** Supplemental public host-loop controls and original/current logs
  are under `artifacts/static-surface/mode-clarification/cylinder-control/`.
  Reproduction inputs above and the maintained cube fixture are sufficient
  without those temporary files.

  the same stock local-stack Dry launch with `CS0246` and zero executed rows.

  This validates the captures without repairing the stock launcher. Current

- **Follow-up:** Audit generated-host compile inputs and dependency-bearing

- **Observed:** 2026-10-13 on Windows x64, during local-stack Release benchmark
  validation of the `EnclosedQ96Coefficient` ownership cleanup. The failing
  process used the frozen pre-cleanup binary, not the extracted implementation.
- **Status:** Low priority, non-blocking; no reliable reproducer. Defer further
  investigation unless the crash recurs, appears in CI or normal simulation, or
  a reliable reproducer becomes available.
- **Evidence:** One fractional-surface changing-mass benchmark process failed
  with `AccessViolationException` inside `MeshRuntimeInertia.TryMaterialize`
  after six warmups and two measured iterations. Its dump shows a scalar-result
  write through an invalid native address containing a coefficient fraction. The
  failed process's timing results are invalid.
- **Uncertainty:** A bounded two-launch follow-up using the same frozen binary
  completed without reproducing the crash. The small dump omits the preceding
  native instructions needed to establish how the invalid address arose. A JIT
  defect is a hypothesis, not a confirmed cause; source review found no unsafe
  operation or escaping reference in the affected path. The observation does not
  establish a defect in the struct extraction.
- **Disposition:** Preserve the failure log, dump and binary identities; do not
  pursue further hardening solely on this observation. An experimental
  raw-output variant passed stress checks, but those checks neither establish
  the original cause nor prove that the variant fixes it.

  `perf/accepted-rca-default-jit.log`, and `perf/rca/` under the same artifact

  terminated with `Fatal error. Internal CLR error. (0x80131506)` before
  producing results. An isolated retry, two complete paired runs and subsequent
